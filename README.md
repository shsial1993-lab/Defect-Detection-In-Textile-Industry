# Industrial Textile Defect Detection with YOLOv8

An object-detection workflow for identifying textile/fabric defects using a fine-tuned Ultralytics YOLOv8 Nano model. The project is implemented as a Google Colab notebook and includes dataset-path preparation, model training, validation, metric reporting, and annotated-image inference.

## Highlights

- Fine-tunes pretrained `YOLOv8n` weights for industrial fabric-defect detection.
- Supports a four-class dataset configured through `data.yaml`.
- Automatically normalizes dataset paths for Google Drive/Colab.
- Trains with 640 × 640 images for 50 epochs and batch size 16.
- Reports precision, recall, F1-score, mAP@50, and mAP@50–95.
- Generates an annotated validation image with predicted bounding boxes and metrics.
- Selects CUDA automatically when a GPU is available and falls back to CPU.

## Dataset Structure

The notebook expects a YOLO-format dataset with the following structure:

```text
FD_Dataset/
└── YOLO/
    ├── data.yaml
    ├── train/
    │   ├── images/
    │   └── labels/
    ├── valid/
    │   ├── images/
    │   └── labels/
    └── test/                 # Optional
        ├── images/
        └── labels/
```

`data.yaml` must contain the dataset class definitions. The notebook preserves the class metadata and updates the `path`, `train`, `val`, and optional `test` locations automatically.

## Environment

The notebook is designed for Google Colab with Google Drive mounted. It was tested in a run using:

- Python 3.12
- PyTorch 2.11 with CUDA 12.8
- Ultralytics 8.4.83
- NVIDIA Tesla T4 GPU

CPU execution is supported, but training and inference will be slower.

## Installation

In Google Colab, run:

```bash
pip install ultralytics pyyaml opencv-python matplotlib
```

The notebook also imports PyTorch. Google Colab normally provides it; for a local environment, install the PyTorch build appropriate for your operating system and hardware from the [official PyTorch website](https://pytorch.org/get-started/locally/).

## Usage

1. Open `Defect_Detection_In_Industry.ipynb` in Google Colab.
2. Mount Google Drive when prompted.
3. Place the dataset under:

   ```text
   /content/drive/MyDrive/Deep Learning/Textile Defect Detection/
   ```

   The notebook supports either of these dataset locations:

   ```text
   .../FD_Dataset/YOLO/data.yaml
   .../YOLO/data.yaml
   ```

4. Run the setup and training cells in order.
5. The model is initialized from `yolov8n.pt` and trained with:

   ```python
   model.train(
       data=yaml_path,
       epochs=50,
       imgsz=640,
       batch=16,
       device=device,
       workers=8,
   )
   ```

6. Run the prediction/evaluation cell to validate the best checkpoint and create an annotated sample image.

## Evaluation Results

The notebook records the following validation results for one trained checkpoint on 73 validation images containing 81 labeled instances:

| Metric | Result |
|---|---:|
| Precision | 0.9353 |
| Recall | 0.8768 |
| F1-score | 0.9051 |
| mAP@50 | 0.9430 |
| mAP@50–95 | 0.5575 |

These values are from the recorded notebook run and may change with a different dataset split, Ultralytics version, random seed, hardware, or training configuration.

## Outputs

After training, Ultralytics saves the run artifacts under the configured `runs` directory, including:

- `weights/best.pt` — checkpoint with the best validation performance.
- `weights/last.pt` — checkpoint from the final epoch.
- Training plots and logs.
- Validation results.

The evaluation cell additionally saves:

```text
runs/evaluation_visual_output.jpg
```

This image contains the predicted bounding boxes, class labels, confidence scores, and a metric banner.

## Important Checkpoint Note

Ultralytics appends a suffix when a run name already exists. Therefore, the actual training directory may be named something like:

```text
runs/figshare_fabric_model-5/
```

Before running inference, confirm that `weights_path` points to the actual `best.pt` file produced by training. The notebook's prediction function currently uses the `figshare_fabric_model-5` example path.

## Model Configuration Note

The active training pipeline uses the pretrained `yolov8n.pt` architecture. The notebook also contains an exploratory custom-tiny YAML section, but that section is commented out and is not the model used for the reported results. A complete YOLO architecture definition is required before training a genuinely custom YAML model.

## Limitations and Next Steps

- The reported validation split is relatively small, so additional testing on unseen production data is recommended.
- Class names are read from the dataset's `data.yaml` and should be documented alongside the dataset release.
- The current inference example selects the first image in the validation directory; replace this with a user-selected image or batch inference for deployment.
- Add confidence-threshold tuning, per-class analysis, and a dedicated test-set report before production use.
- Add a license and dataset citation before redistributing the code or data.
